# Authored assessment execution

Today assessment suggestions use an active AssessmentRubric from the frozen Recommendation candidate. Before starting, the learner selects an eligible active `exercise` or `practice_task` LearningUnit from the same Curriculum version with an assessment EvidenceOpportunity and at least one target criterion covered by the rubric. The exact matching Unit target must be suitable and the Unit's hard availability and readiness requirements must be met. Suitability of another target on the Unit cannot make the rubric target eligible. Resource and verification-template Units are not offered as executable assessment tasks. If no task qualifies, no Activity or Session is created.

Starting atomically creates an Activity, a timed LearningSession, an Activity-to-Unit link, the Today start relation, and an `assessment_executions` row. The execution pins the exact rubric, Curriculum version, Unit, opportunity, Recommendation run/candidate, Today suggestion, competency, Activity, and Session. The learner selects one of the canonical assistance modes; the Session record is authoritative. Session completion alone creates no criterion result. Existing generic Session Evidence can still be recorded, but it does not inherit a reviewed criterion outcome.

## First-party review policy

`first-party-assessment-review/v1` is a structured **self-review** policy. It is not external assessor verification or automated grading. A completed, non-cancelled Session with actual duration is required. The authenticated learner must attest that the observations belong to that Session, assistance is fully disclosed to the best of their knowledge, outputs are authentic, and the criterion decisions reflect what was observed. Medium source confidence also requires a task artifact uploaded as bytes to LCC. LCC stores those bytes in immutable `assessment_artifacts` history, computes SHA-256 itself, and binds the record to the execution, Session, selected Unit/opportunity, and criterion. Narrative fields, attestation, free-text `artifact_content`, external references, and caller-supplied hashes alone remain Low, even when the authored opportunity marks artifacts optional. An opportunity that requires an artifact still requires a server-stored artifact for qualifying review Evidence. Review rows must match exactly the criterion definitions shared by the pinned rubric and selected Unit target. Unobserved rows create no Evidence. Rubric weights never determine a result.

For a reviewed criterion, the learner records task setup, expected result, actual output, and a comparison. To qualify for Medium, the learner separately uploads an actual task artifact or preserved output file (up to 256 KiB) after finalizing the Session and selects that server-stored artifact in the criterion review. The review request references only its ID; the server verifies the stored bytes, hash, and exact source lineage. A structurally complete first-party observation with a valid stored artifact can receive **Medium source confidence**. Incomplete or narrative-only observations receive Low. Medium means well-provenanced first-party review, not independently checked correctness. The policy does not infer correctness from prose: the reviewer explicitly chooses demonstrated, partial, or contradicted and attests to the actual observation. The comparison must describe the relevant success, failure, and boundary behavior required by the authored task; this is a human judgment that the server cannot machine-verify from the current authored rubric.

Evidence strength is separate. A complete demonstrated or contradicted observation can produce Moderate strength only if the selected opportunity allows Moderate; otherwise it is Weak. Partial observations are Weak. V1 never emits Strong assessment Evidence. The server derives confidence, strength, effect, independence, and criterion link; callers cannot submit those fields. A complete contradicted result links with `contradicts` and a complete demonstrated result with `supports` only when the opportunity permits the derived strength and assistance. Partial, incomplete, unsupported-mode, and agent-led observations link with `context_only`, so they cannot satisfy even an exposure rule. The effective assistance mode is the more conservative of the Session mode and any additional disclosed help: `none` and `docs_only` are independent; `ai_hint` and `ai_assisted` are assisted; `agent_led` is guided but never qualifying learner performance in this policy. If the opportunity excludes a mode, the observation cannot receive Medium. Reviewer identity and `reviewer_kind=self` remain in immutable review and Evidence provenance.

Each review is append-only. A correction names the prior review and reason, appends a new snapshot, retracts the prior review's Evidence, and evaluates capability from active Evidence. Session correction or cancellation retracts assessment Evidence; correcting assistance requires a new review under the corrected Session provenance. For assessment Evidence, the Session is the occurrence identity. Several artifacts, rows, or links in one Session cannot satisfy a two-occurrence criterion. A second qualifying occurrence requires another actual Session, and the existing evaluator's context rules still apply.

Evidence creation evaluates capability and review state through existing projection invalidations. Roadmap and Analysis become stale as appropriate. New Analysis, Recommendation, and Today runs require explicit action; their historical runs remain immutable. A finalized assessment Session awaits review; Today cannot close the assessment suggestion until its bound execution has a valid review. The execution detail route `/assessments/{executionId}` remains reachable from Activity history across Today generations, local days, and recent Session list limits. A started assessment from before task-bound execution support has no execution and cannot be retroactively reviewed. Today explains the legacy state and can atomically correct the old start and create a distinct, newly bound attempt after the old Session is finished. Portable V11 includes `assessment_executions`, `assessment_artifacts`, and `assessment_reviews` and rejects inconsistent source Session, artifact integrity, or review Evidence lineage; V10 and earlier restore with empty assessment history. V10's frozen manifest and table contract are unchanged.

## Current limits

The policy relies on a truthful first-party attestation and actual submitted artifact bytes. Server custody and hashing do not prove that the learner produced the artifact or that its contents are technically correct. An authored Unit may cover only part of a rubric; other criteria remain unobserved. V1 cannot issue Strong Evidence, and a single Moderate independent assessment cannot satisfy a criterion requiring two distinct Moderate occurrences. Broader or machine-checkable tasks require a future authored Curriculum successor.
